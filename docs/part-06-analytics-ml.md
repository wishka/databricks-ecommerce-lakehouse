### Собрать AI/BI Dashboard

1. **Dashboards → Create dashboard**.
2. Вкладка **Data**: добавьте датасеты, вставив SQL из `sql/queries/`.
3. Вкладка **Canvas**: виджеты
   * line chart — выручка по дням (из `01`);
   * bar chart — топ категорий;
   * counter — выручка за период и её изменение;
   * heatmap — когорты (из `02`);
   * funnel/bar — воронка (из `03`);
   * table — клиенты с высоким риском оттока (из `gold.customer_churn_scores`).
4. **Фильтры**: параметры `date_from`, `date_to`, `channel` привяжите к
   датасетам — один фильтр управляет всеми виджетами.
5. **Schedule**: обновление раз в сутки после ночной джобы.

Практический совет: 5–7 виджетов, отвечающих на конкретные вопросы, лучше
двадцати «на всякий случай». Дашборд, который никто не открывает, — техдолг.

### Alerts

`sql/queries/04_alerts.sql` содержит четыре запроса, каждый возвращает одно число:
падение выручки, блокирующие нарушения качества, «конвейер не отработал»,
рост доли отмен. **SQL → Alerts → Create alert**, условие + расписание + получатель.

Алерт на «конвейер не отработал» (часы с последнего запуска > 26) полезнее
всех остальных: тихо не приехавшие данные опаснее приехавших плохо.

### Главное: утечка целевой переменной

Фичи считаются строго на `as_of_date`, метка — по окну после неё.
`as_of_date = max(order_date) - 30 дней`, чтобы после отсечки осталось
достаточно данных для метки.

Признак утечки: одна фича даёт AUC 0.99. Проверяйте средние значения фич
по классам — если различие драматическое и необъяснимое, вы посчитали фичу
по данным из будущего.

### Реестр моделей в Unity Catalog

```python
mlflow.set_registry_uri("databricks-uc")
mlflow.sklearn.log_model(..., registered_model_name="ecom_dev.ml.churn_model")
```

Модель становится объектом каталога: у неё есть права, версии и lineage.
Алиас `@champion` — стабильная ссылка, по которой скорит батч-джоба;
переключение чемпиона не требует правки кода инференса.

Промоушен с проверкой: новая версия становится чемпионом, только если её
ROC-AUC выше текущего чемпиона, иначе получает алиас `challenger`.
Такого gate обычно не хватает в учебных проектах — и именно он отличает
«я обучил модель» от «у меня есть контур обновления модели».

### Батч-инференс

```python
predict = mlflow.pyfunc.spark_udf(spark, "models:/ecom_dev.ml.churn_model@champion")
scored = features.withColumn("churn_probability", predict(*input_columns))
```

Рядом со скором пишем `model_version` и `scored_at` — без этого невозможно
разобраться, какой моделью посчитано конкретное число.

### Мониторинг дрейфа

`ops.churn_score_history` копит распределение предсказаний по запускам.
Резкий сдвиг средней вероятности — сигнал, что изменились данные или пора
переобучать. На платном воркспейсе то же делает Lakehouse Monitoring
(`CREATE MONITOR` на таблице со скорами).

## Частые проблемы

**`mlflow.set_registry_uri("databricks-uc")` и ошибка прав** — нужны
`CREATE MODEL` на схеме `ml` и `USE CATALOG`/`USE SCHEMA`.

**`spark_udf` падает на типах** — модель сохранена без сигнатуры либо колонки
таблицы фич не совпадают с обучающими. Сигнатура для того и нужна.

**AUC около 0.5** — метка вырождена (все ушли или никто). Увеличьте период
генерации данных в Part 0 или уменьшите `label_window_days`.

**Genie отвечает мимо** — почти всегда дело в отсутствии комментариев
и примеров вопросов, а не в модели.
